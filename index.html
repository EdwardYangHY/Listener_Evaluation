Multi-Speaker Conversational Speech-to-Speech Translation

Audio samples on real two-speaker meeting and conversation recordings (AMI, ICSI, AliMeeting, RAMC), English ↔ Chinese. Each sample plays the source conversation, then the translated conversation from our model and three baselines.
English → Chinese · Chinese → English Transcript:
COMUS (ours)End-to-end: one model jointly diarizes, translates and generates each speaker's voice.
S2TT + TTSQwen3-Omni fine-tuned on the same data for diarization + speech-to-text translation, then CosyVoice3 voice-cloning TTS.
Cascadepyannote Community-1 diarization (told there are 2 speakers) → ASR → Qwen3-Omni conversation-level MT → CosyVoice3 TTS.
SD + UniSSpyannote 3.1 diarization → UniSS single-speaker S2ST per segment.
  • All samples are from held-out test splits; none were seen in training.
  • More samples from the original submission: anonysample.github.io/E2E-CoT-MultiTalker-S2ST
  • By default the text under each player is an automatic transcription of that system's output audio, turn by turn, so it shows what is actually spoken, including speech-synthesis errors. The same ASR is used for every system (Paraformer for Chinese, Whisper small.en for English; Chinese ASR output has no punctuation). The ASR can itself mishear a word, mostly names, so judge by listening; the transcript is a guide. Switch to "text the system generated" to see the translation each system intended to say (for the cascades, the text sent to TTS).
  • The source transcript is the human reference transcript. Speaker numbers follow each system's own diarization, in order of first appearance, so they need not match the source numbering.
  • The cascade systems synthesize each turn separately and join the turns back to back; very short backchannels (e.g. 嗯。) are not synthesized. In the transcription view, turns in which the ASR recognizes no speech are not listed.
